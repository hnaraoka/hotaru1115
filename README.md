# 月次報告書作成アプリ

Next.js (Node.js) + Prisma + PostgreSQL で構築した、SES常駐エンジニア向け月次報告書の作成・保存・一覧表示・PDF出力ができるアプリです。Vercel へのデプロイを想定しています。

## 開発状況

計画していた全フェーズ（Phase 1〜7）を実装済みです。

- [x] Phase 1: データモデル刷新＋認証基盤（NextAuth・ユーザー管理画面・ログイン画面・失敗回数通知）
- [x] Phase 2: 月次報告書フォーム＋バリデーション＋保存
- [x] Phase 3: PDF出力（レイアウト再現・円グラフ含む）
- [x] Phase 4: 前月データ引き継ぎ
- [x] Phase 5: Resendメール通知＋画面内通知の仕上げ（Phase 1で実装済み）
- [x] Phase 6: 過去PDF読み込み（固定テンプレート解析）
- [x] Phase 7: モバイル最適化・全体QA

## Phase 1 で実装した機能

- **管理者によるユーザー管理**: ログインID・氏名・権限（管理者/一般）を指定してアカウントを作成すると、初期パスワードが自動発行され画面に表示されます（管理者が口頭で伝達）。編集画面から権限変更・パスワード再発行（ランダム発行または任意の文字列を直接指定）・アカウント無効化ができます。パスワードを変更した際、対象ユーザーにメールアドレスが登録されていればResend経由で新しいパスワードを自動通知します（未設定時は口頭などで伝達）。一般ユーザー（一般権限）のアカウントは編集画面から削除でき、削除すると紐づく月次報告書も併せて削除されます（管理者アカウントは削除不可）。
- **CSVによるユーザー一括登録**: ユーザー管理画面の「CSVで一括登録」から、ログインID・氏名・権限・メールアドレスを記載したCSVファイルをアップロードして複数アカウントをまとめて作成できます。作成前にプレビュー表示で内容を確認でき、作成後は各行の成否と初期パスワードの一覧をCSVでダウンロードできます。
- **一般ユーザーによるパスワード変更**: 権限に関わらず、ログイン中のユーザーはヘッダーの「パスワード変更」から現在のパスワードを確認したうえで自分でパスワードを変更できます。
- **ログイン画面**: ログインID・パスワードでログイン。3回連続で失敗すると、管理画面の通知一覧に記録され、管理者アカウントにメール通知（Resend、未設定時は画面内通知のみ）が送信されます。3回失敗した時点から15分間はそのアカウントでのログインをロックし、総当たり攻撃を防ぎます（直近の失敗から15分経過すると自動的に解除。管理者がパスワードを再発行/変更した場合も即座に解除されます）。
- **提出状況ダッシュボード**: 管理者は「提出状況」画面から、対象月ごとに全ユーザーの月次報告書の提出済み/未提出を一覧で確認できます。
- **権限制御**: `/admin/**` は管理者のみアクセス可能。未ログインのアクセスは自動的に `/login` へリダイレクトされます。

## Phase 2 で実装した機能

- **月次報告書フォーム**: 提出日・対象年月・参画先企業・作業場所・月間実労働・技術スタック（言語/FW/DB/ツール/OS・タグ入力）・プロジェクト期間・作業内容・開発工程（チェックボックス）・成果物・所感・自己評価（5段階×6項目）・作業配分（自由項目＋割合）を入力できます。
- **バリデーション**: 必須項目・開発工程1つ以上選択・作業配分の合計100%チェックをクライアント側（Zod）とサーバー側APIの両方で実施します。同一ユーザー・同一対象月の重複作成はサーバー側で防止されます。
- **一覧・詳細・編集・削除**: ログインユーザー本人の報告書のみ閲覧・編集・削除できます（管理者は全件アクセス可）。

## Phase 3 で実装した機能

- **PDF出力**: 詳細画面の「PDFを開く」「PDFをダウンロード」から、元のExcel帳票に近いレイアウトのPDFを生成します（提出者情報・参画先・技術スタック・開発工程チェック・自己評価・作業配分の円グラフなど）。
- **日本語フォント対応**: Noto Sans JP（フルセット）を同梱し、常用漢字外の漢字や○記号などを含め文字化けなく描画します。
- **作業配分の円グラフ**: ユーザーが自由に追加した項目を、検証済みの識別性カラーパレット（8色固定順）で描画します。9項目を超える場合は上位7項目＋「その他」に集約されます。

## Phase 4 で実装した機能

- **前月データの引き継ぎ**: 新規作成画面を開くと、ログインユーザーが直近に作成した報告書を自動取得し、対象年月を「その翌月」にあらかじめ設定します。「前回のデータを引き継ぐ」ボタンを押すと、参画先企業・作業場所・技術スタック・プロジェクト名・期間開始・開発工程など月をまたいで変わりにくい項目のみを引き継ぎます。作業内容・成果物・困った点・良かった点・自己評価・作業配分など今月固有の項目は空欄のまま、毎月あらためて入力します。

## Phase 6 で実装した機能

- **過去PDF（Excel由来）の読み込み**: 新規作成画面の「PDFから読み込む」で、これまで手作業でExcelから出力していた月次報告書PDFをアップロードすると、`pdfjs-dist` で文字とその座標を抽出し、この帳票テンプレート専用のロジックで項目ごとに解析してフォームへ自動入力します（提出者情報・参画先・月間実労働・技術スタック・プロジェクト期間/内容・開発工程チェック・成果物・所感・自己評価まで対応）。
- **既知の制限**: 円グラフの「作業配分」は割合(%)を自動抽出できないため、項目名のみ引き継いで均等割り（合計100%）にしています。読み込み後は必ず内容を確認し、実際の割合や誤読の可能性がある項目を修正してから保存してください。このパーサーは今回対応した帳票テンプレートに特化しており、レイアウトが大きく異なるPDFでは正しく読み込めない場合があります。

## Phase 7 で実装した機能

- **モバイル対応の調整**: スマートフォン幅（375〜390px程度）でヘッダーのナビゲーションが崩れていた問題、報告書詳細画面のPDF操作ボタンが折り返し時に単語の途中で改行されてしまう問題を修正しました。フォーム・一覧・管理画面は元々レスポンシブなグリッド/flexレイアウトで実装していたため、大きな崩れはありませんでした。
- **全体QA**: 認証・管理者機能・報告書CRUD・PDF出力・前月引き継ぎ・過去PDF読み込みを通しで再確認し、編集後のデータ保存や削除が正しく動作することを確認しました。

## 技術構成

- [Next.js](https://nextjs.org)（App Router / TypeScript）
- [Prisma](https://www.prisma.io) + PostgreSQL（データの保存）
- [NextAuth (Auth.js) v5](https://authjs.dev) + bcryptjs（ID/パスワード認証）
- [Resend](https://resend.com)（ログイン失敗の管理者宛メール通知。未設定時は画面内通知のみ動作）
- [@react-pdf/renderer](https://react-pdf.org)（サーバーサイドPDF生成。Noto Sans JP フルセットフォントを同梱）
- [pdfjs-dist](https://mozilla.github.io/pdf.js/)（過去PDFの文字・座標抽出。`next.config.ts` の `serverExternalPackages` でバンドル対象外にしています）

## セットアップ（ローカル開発）

### 1. 依存パッケージのインストール

```bash
npm install
```

### 2. 環境変数の準備

```bash
cp .env.example .env
```

- `DATABASE_URL`: PostgreSQL の接続文字列
- `AUTH_SECRET`: `openssl rand -base64 32` などで生成したランダム文字列
- `AUTH_TRUST_HOST`: ローカル開発や Vercel 以外の環境では `true` を設定
- `RESEND_API_KEY` / `NOTIFY_FROM_EMAIL`: 管理者へのメール通知を使う場合に設定（未設定でも動作します）

### 3. マイグレーションの適用

```bash
npx prisma migrate dev
```

### 4. 初期管理者アカウントの作成

```bash
npm run db:seed
```

デフォルトでは ログインID: `admin` / パスワード: `ChangeMe123!` が作成されます。`SEED_ADMIN_LOGIN_ID` / `SEED_ADMIN_PASSWORD` / `SEED_ADMIN_NAME` / `SEED_ADMIN_EMAIL` 環境変数で上書きできます。ログイン後は管理画面からパスワードを再発行してください。

### 5. 開発サーバーの起動

```bash
npm run dev
```

[http://localhost:3000](http://localhost:3000) を開いてください。

## Vercel へのデプロイ

1. このリポジトリを Vercel にインポートします。
2. **Storage** タブから Vercel Postgres（または任意の PostgreSQL、例: Neon / Supabase）を作成し、プロジェクトに接続します。接続すると `DATABASE_URL` 環境変数が自動的に設定されます（自動設定されない場合は Project Settings > Environment Variables で手動設定してください）。
3. `AUTH_SECRET` を Project Settings > Environment Variables に設定します。
4. （任意）管理者へのメール通知を使う場合は `RESEND_API_KEY` / `NOTIFY_FROM_EMAIL` を設定します。
5. 初回デプロイ前後に、マイグレーションと初期管理者アカウント作成を実行します（`DATABASE_URL` をデプロイ先のデータベースに向けた状態で実行してください）。

   ```bash
   npx prisma migrate deploy
   npm run db:seed
   ```

6. デプロイを実行します。`npm run build` は自動的に `prisma generate` を実行してから `next build` を行います（`postinstall` でも `prisma generate` を実行するため、Vercel のキャッシュ環境でも Prisma Client が生成されます）。

## PDFの日本語フォントについて

`src/fonts/` に Noto Sans JP（OFL ライセンス、フルセット）を同梱しています。react-pdf はフォントに含まれない文字を正しくフォールバックせず文字化けする（別の文字に置き換わる）ため、常用漢字外の人名・専門用語なども含めて安全に描画できるよう、あえてサブセット化せずフルセットを採用しています（フォントファイルはRegular/Boldそれぞれ約5MB）。
